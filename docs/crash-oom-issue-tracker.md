## Fix policy

- Confirm the failure from logs, a reproduction or a code path before assigning a root cause.
- Search canonical issues and related pull requests before starting each fix; keep independent problems in separate changes.
- Fix the shared cause at the layer that owns it, preserve existing error handling, and add focused backend regression coverage where applicable.
- For every issue actually resolved by a PR, use a PR body containing only the factual fix description and `fixes: #<number>` for each resolved issue. Use `related to:` only for issues not resolved by that PR.
- Do not mark an issue fixed from a workaround, a closed issue state, or a passing build alone.
