# Open bug and stability milestone

This local milestone proposal covers all 51 issues currently labeled `bug` and open in Metrolist as of 2026-11-20, plus the unlabelled open crash report #5039. No issue is open with the `crash` label, and searches found no open OOM or out-of-memory report. The [crash, OOM and stability tracker](crash-oom-issue-tracker.md) includes the wider issue scan and closed reports. Each independent root cause belongs in a separate PR. Existing PRs stay with their current authors and remain listed for tracking.

The canonical GitHub milestone could not be created: the connected account has read-only permission on `MetrolistGroup/Metrolist`. The list is ready to attach when an account with triage or write permission is available.

- #5072 reports Windows 14.0.1. The AWT dispatcher exposes layout-dependent virtual key codes, so PR #5078 captures Windows low-level keyboard scan codes only while a Metrolist window is active; letters still match the produced character. Follow-ups `b5966ca5d`, `904536823` and `4276a22f3` keep capture queues stable across hook/EDT races, serialize expiration, retain worker ownership through shutdown and register the callback for native-image. Mapping tests pass on Linux; an actual Windows AZERTY check is still required.
- #5076 includes a macOS 26.2 stackshot from a 4-second hang and a JVM thread dump. AppKit accessibility calls `invokeAndWait` while AWT's event queue is blocked in the Compose WebView Wry `load_url` JNI call; the native stack shows a synchronous dispatch wait. The pinned [Wry WebView implementation](https://github.com/kdroidFilter/ComposeDesktopNativeWebiew/blob/v1.0.0-beta-02/wrywebview/src/main/kotlin/io/github/kdroidfilter/webview/wry/WryWebViewPanel.kt#L106-L133) calls native `loadUrl` directly on the EDT and posts it to the EDT from other threads, matching the reported wait cycle. One reporter retested successfully with `COMPOSE_DISABLE_ACCESSIBILITY=1`, which suggests an accessibility/WebView interaction but does not establish the root cause. A fix needs a dependency-level nonblocking native dispatch and macOS reproduction; do not disable accessibility globally.
- #5036's v14.0.1 APK differs because its bundled libopus version string includes `git describe` output, which differs when the submodule clone has no tags. Commit `dd5ab31e0` on `main` stops embedding that Git-derived string. v14.0.1 remains affected; no v14.1.0 release is published yet, and the maintainer plans to keep the issue open until it is.

A restore whose local server fails to start leaves the preference enabled but runtime state inactive, so the screenshot alone cannot distinguish preference loss from restoration/server failure.
